언리얼 엔진

Mixamo 애니메이션을 리타겟하면 Root Motion이 어긋나는 문제

2026.10.20 6분 분량

들어가며

Mixamo에서 받은 공격 애니메이션을 프로젝트의 SwordMan 캐릭터에 적용하려고 했습니다. Mixamo 애니메이션에는 Root Bone이 없어 Root Motion을 쓸 수 없습니다. 그래서 블렌더에서 Root Bone을 추가한 뒤 언리얼로 가져와 리타겟하는 방식으로 진행했습니다.

Mixamo (X_Bot)
   ↓  블렌더 애드온으로 Root Bone 추가 후 FBX 내보내기
언리얼 (X_Bot_Skeleton)
   ↓  IK Retargeter
SwordMan 애니메이션 → 애니메이션 몽타주

Root Bone은 블렌더 Extensions에 등록된 Import Mixamo - Root Motion 애드온으로 추가했습니다. Mixamo FBX 폴더를 지정해 가져오면 Root Bone을 만들고, Hips에 있던 이동을 Root Bone으로 옮기는 베이크까지 자동으로 처리해 줍니다.

그런데 리타겟한 애니메이션을 재생하자 문제가 연달아 나타났습니다.

  • 다리가 움직이지 않음
  • 팔이 원본 동작과 다른 방향을 향함
  • Root Motion을 켜도 캐릭터가 앞으로 나가지 않음
  • 공격할 때 카메라가 흔들림

증상이 여러 가지라 하나씩 원인을 확인했습니다.

다리가 움직이지 않는 문제

처음에는 애니메이션을 우클릭해 Retarget Animations로 리타겟했습니다. 이 방식은 IK Rig와 IK Retargeter를 자동으로 만들어 주는데(IK_AutoGeneratedSource, RTG_AutoGenerated), 자동 생성된 소스 IK Rig를 열어 보니 다리 체인이 하나도 잡혀 있지 않았습니다.

원인은 블렌더를 거치면서 바뀐 본 이름이었습니다. 자동 생성 기능은 mixamorig:LeftUpLeg 같은 Mixamo 본 이름 규칙으로 다리를 찾는데, 언리얼로 들어온 스켈레톤의 본 이름은 다음처럼 바뀌어 있었습니다.

mixamorig:LeftUpLeg   →  upleg_L
mixamorig:LeftLeg     →  leg_L
mixamorig:LeftFoot    →  foot_L
mixamorig:LeftToeBase →  toebase_L

블렌더의 아웃라이너를 보니 애드온으로 가져오는 단계에서 이미 upleg.L처럼 블렌더 방식의 이름으로 바뀌어 있었고, 이 이름이 언리얼에서 upleg_L로 들어온 것이었습니다.

다리 체인이 없으니 다리는 애니메이션을 받지 못하고 기본 포즈에 머물러 있었고, 골반과 상체만 애니메이션대로 회전했습니다. 몸을 크게 트는 공격 동작에서 상체만 돌아가다 보니 그 사이에 있는 허리가 꼬인 것처럼 보였던 것입니다.

자동 생성 대신 IK Rig를 새로 만들어 체인을 하나씩 지정했습니다. 이때 SwordMan의 IK Rig는 다리를 LeftLeg(허벅지~발목)와 LeftFoot(발)으로 나누고 있어서, 소스도 같은 구조로 맞췄습니다.

체인 소스(X_Bot) 본
Spine spine ~ spine2
LeftArm arm_L ~ hand_L
LeftLeg upleg_L ~ foot_L
LeftFoot toebase_L

처음에는 소스의 LeftLeg를 발가락까지 하나로 묶었는데, 체인 이름뿐 아니라 체인이 어디서 끝나는지도 양쪽이 같아야 했습니다.

팔이 다른 방향을 향하는 문제

다리를 고치고 나니 이번에는 팔이 맞지 않았습니다. Mixamo는 T-포즈, SwordMan은 A-포즈라서 리타겟 포즈를 맞추기 위해 소스 쪽에 Auto Align을 적용해 둔 상태였습니다.

언리얼 에디터에서 Python 스크립트로 두 스켈레톤의 본 트랜스폼을 출력해 비교해 보니, 소스의 root 본에 블렌더에서 넘어온 회전(Roll 90°)과 스케일(100) 값이 남아 있었습니다.

X_Bot root    rot(P,Y,R) = (0, 0, 90)   scale = 100
SwordMan root rot(P,Y,R) = (0, 0, 0)    scale = 1

같은 프레임에서 왼쪽 위팔이 향하는 방향을 계산해 보니 원본과 결과가 약 33° 어긋나 있었습니다. T-포즈와 A-포즈의 팔 각도 차이(약 36°)와 거의 같았기 때문에, 소스 쪽 Auto Align이 root의 회전 때문에 팔을 잘못 돌려 놓았다고 판단했습니다.

소스는 원래 T-포즈로 두고, root에 회전이 없는 타겟 쪽을 소스에 맞춰 Auto Align 하는 방식으로 바꾸자 팔이 원본 동작을 따라갔습니다.

Root Motion이 적용되지 않는 문제

애니메이션 시퀀스에서 Enable Root Motion을 켜도 캐릭터가 앞으로 나가지 않았습니다. 공격하면 메시만 캡슐을 벗어났다가 끝나는 순간 제자리로 돌아왔습니다.

리타겟 전후의 Root Bone 이동량을 출력해 보니 원인이 바로 보였습니다.

root    이동 (0, 245.0, 0)    ← 소스(X_Bot)
root    이동 (0, 0, 0)        ← 리타겟 결과
pelvis  이동 (0, 144.9, 0)    ← 리타겟 결과

애드온이 베이크한 대로 소스에는 Root Bone 이동이 들어 있었지만, 리타겟 결과에서는 골반만 앞으로 나가고 root는 제자리였습니다. Root Motion은 Root Bone의 이동만 캐릭터 이동으로 바꾸기 때문에 캐릭터가 움직이지 않았던 것입니다.

IK Retargeter의 Root Motion op를 확인해 보니 Source Root와 Target Root가 비어 있었습니다. 타겟 IK Rig에 Root 체인이 없어서 자동으로 잡히지 않은 것으로 보입니다. 다음처럼 설정한 뒤 다시 내보내자 root가 골반을 따라 이동했습니다.

설정 값
Source Root / Target Root root
Root Motion Source Generate From Target Pelvis
Root Height Source Snap To Ground

소스 Root Bone을 그대로 복사하지 않고 타겟 골반에서 새로 만든 이유는, 앞에서 본 것처럼 소스 root에 블렌더의 회전이 남아 있었기 때문입니다.

공격할 때 카메라가 흔들리는 문제

Root Motion이 동작하자 공격할 때 카메라가 흔들렸습니다. Generate From Target Pelvis는 골반의 수평 이동을 그대로 Root Bone에 옮기는데, 칼을 휘두를 때 골반은 앞으로만 가지 않고 좌우로도 움직입니다. 확인해 보니 Root Bone이 좌우로 최대 47.8만큼 움직이고 있었고, 캡슐과 그 뒤를 따르는 카메라도 함께 흔들렸습니다.

에디터의 Python 스크립트로 애니메이션의 키를 고쳐 Root Bone의 좌우(X) 이동을 0으로 만들고, 뺀 값은 골반에 더했습니다.

root   X  →  0
pelvis X  →  pelvis X + root X

이렇게 하면 화면에 보이는 몸의 움직임은 그대로이고, 캡슐과 카메라만 흔들림 없이 앞으로 이동합니다.

마치며

결과적으로 네 가지 증상은 서로 다른 단계에서 생긴 문제였습니다. 다리와 팔은 블렌더를 거치며 바뀐 본 이름과 Root Bone의 회전 때문이었고, Root Motion과 카메라 흔들림은 IK Retargeter의 Root Motion 설정 때문이었습니다.

리타겟한 애니메이션의 Root Motion은 다음 경로를 거쳐 만들어지며, 블렌더의 Root Bone과 IK Retargeter의 설정이 모두 결과에 영향을 줍니다.

Mixamo FBX
   ↓  블렌더 애드온 (Root Bone 추가, 이동 베이크)
언리얼 X_Bot
   ↓  IK Retargeter (Root Motion op: 타겟 골반 → root)
SwordMan 애니메이션의 root 이동
   ↓
캡슐 이동 → 카메라 이동
