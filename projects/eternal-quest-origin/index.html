팀 프로젝트 2024

Eternal Quest: Origin

언리얼 온라인 서브시스템과 Steamworks SDK로 스팀 플랫폼 연동, 게임 세션 관리, 캐릭터 직업 정보 동기화, 비동기 에셋 최적화를 적용한 온라인 RPG입니다.

게임 소개
언리얼 온라인 서브시스템을 활용한 온라인 RPG
진행 기간
2024.02.05 ~ 2024.03.13
개발 인원
프로그래머 3명
사용 기술
C++, Unreal Engine, Online Subsystem, Steamworks SDK, Git
담당 파트
멀티플레이어 네트워크 환경 구축 및 Steam 플랫폼 연동
직업별 이동·공격·스킬 컴포넌트 제작 및 네트워크 동기화

주요 구현

멀티플레이어 네트워크 통합

  • Online Subsystem Steam과 Steamworks SDK를 연동해, IP 입력 없이 Steam 로비로 세션을 검색·참가하는 매칭 구현
  • 세션 설정에서 Presence와 로비를 사용하고 게임 도중 참가를 허용, 매치 타입을 광고해 검색 시 필터링
  • 서브시스템 종류에 따라 LAN 여부를 자동 전환해 로컬 테스트와 Steam 환경을 같은 코드로 처리
  • 기존 세션이 남아 있으면 파기 완료 후 재생성하도록 처리해 세션 중복 방지

발행-구독 기반 게임 세션 관리

  • 세션 생성·검색·참가·파기 완료 콜백을 델리게이트 핸들로 등록하고, 완료 시 해제해 중복 호출 방지
  • 결과를 자체 멀티캐스트 델리게이트로 발행해, UI가 세션 처리 로직을 직접 참조하지 않도록 분리
  • 세션 요청이 즉시 실패하거나 검색 결과가 없으면 곧바로 실패를 발행하고 핸들을 정리해, UI가 응답 없이 대기하지 않도록 처리

캐릭터 직업 정보 동기화

  • 로컬 GameInstance의 직업 선택 정보를 Server RPC로 서버에 전달
  • 서버는 전달받은 직업을 적용한 뒤, 호스트의 직업을 Client RPC로 회신해 서로의 직업 교환
  • 로그인 화면에서 입력한 사용자 이름도 같은 RPC 흐름으로 교환해 머리 위 이름 위젯에 표시

비동기 에셋 로딩

  • 시작 시 모든 직업 에셋을 한 번에 로드하던 방식을, 직업이 확정된 시점에 필요한 파츠만 불러오는 방식으로 전환
  • 에셋 경로만 보관하고 StreamableManager의 RequestAsyncLoad로 파츠별 비동기 로드
  • 로드 완료 전까지 파츠 메시를 숨겨 기본 외형이 잠깐 보이는 현상 방지
  • 파츠별 로드 완료 델리게이트에서 메시를 적용하고 핸들 해제

설계와 문제 해결

직업 정보 동기화 문제 추적

  • 다른 플레이어 화면에서만 캐릭터가 잘못된 직업으로 표시되는 문제가 발생해, 처음에는 에셋 로딩 문제로 의심
  • 흐름을 단계별로 추적한 결과, 직업 정보가 복제되지 않는 GameInstance에만 저장된 것이 원인
  • 서버를 거쳐 직업 정보를 교환하도록 바꾼 뒤 양쪽 화면의 외형 일치 확인

네트워크 초기화 시점 추적

  • 직업·이름을 적용할 시점이 서버와 클라이언트에서 달라, PossessedBy·OnRep_PlayerState 등에 로그를 넣어 초기화 순서 추적
  • 서버는 컨트롤러가 폰을 소유하는 PossessedBy, 클라이언트는 PlayerState가 복제되는 OnRep_PlayerState 시점에 직업·이름 갱신을 연결
  • 두 경로에서 같은 갱신 함수를 호출해, 초기화 경로가 달라도 동일한 로직으로 처리

로컬 플레이어 전용 처리 분리

  • 모든 플레이어 캐릭터가 같은 클래스를 쓰기 때문에, 미니맵 캡처·입력 등록 같은 처리가 다른 플레이어의 캐릭터에서도 실행될 수 있는 구조
  • IsLocallyControlled로 로컬 플레이어 캐릭터에서만 미니맵 렌더 타겟을 생성해 씬 캡처와 연결하고, Enhanced Input 매핑 컨텍스트도 로컬 컨트롤러에만 등록
  • 다른 플레이어 캐릭터에서는 이 처리를 건너뛰어 불필요한 씬 캡처 렌더링과 입력 중복 등록 방지

RPC 기반 공격·스킬 동기화

  • 공격·스킬 입력 시 가능 여부를 확인한 뒤 Server RPC로 요청하고, 서버가 NetMulticast RPC로 모든 클라이언트에서 같은 동작을 실행하도록 구성
  • 직업에 따라 분기해 몽타주 섹션 단위로 재생하고, 몽타주 종료 델리게이트에서 이동과 판정을 마무리
  • 텔레포트는 LineTrace로 장애물 앞까지만 이동하고, 스윕 이동으로 벽 관통 방지

캐릭터 콤보 공격

  • 콤보별 입력 허용 구간을 데이터 에셋의 유효 프레임 수로 계산해 타이머로 관리
  • 구간 안에 들어온 입력만 다음 몽타주 섹션으로 연결하고, 입력이 없으면 몽타주 종료 시 초기 상태로 복귀
  • 최대 콤보 수·섹션 이름·판정 프레임을 데이터 에셋으로 분리해, 애니메이션을 바꿔도 코드 수정 없이 조정 가능

사망과 리스폰 처리

  • 체력이 0이 되면 스탯 컴포넌트의 델리게이트로 사망 처리를 호출하고, Server RPC와 NetMulticast RPC로 사망 상태 전달
  • 사망 시 이동과 게임 입력을 막고 충돌을 끈 뒤 사망 몽타주를 재생하며, 체력 바를 숨김
  • 10초 뒤 타이머로 플레이어 스타트 위치에서 부활시키고, 입력과 스탯을 복원한 뒤 부활 몽타주 재생

컴포넌트 기반 캐릭터 구조 설계

  • 이동·공격·스킬·스탯·인벤토리·퀘스트를 컴포넌트로 분리해 캐릭터 클래스의 의존성 축소
  • 모든 컴포넌트가 공통 베이스 클래스의 SetupPlayerInput을 재정의하는 구조로, 새 컴포넌트도 같은 방식으로 추가 가능
  • 입력 컴포넌트를 델리게이트로 발행해 각 컴포넌트가 자기 입력을 바인딩, 스탯 변화도 델리게이트로 UI에 연결

3인 팀 협업 체계

  • 팀원마다 코드 스타일이 달라 의도 파악이 어려워, 언리얼 공식 코딩 표준으로 명명 규칙과 주석 방식 통일
  • 동시 작업으로 충돌이 잦아 Git 브랜치 정책·커밋 규칙·.gitignore로 작업을 분리하고 저장소 관리
  • 결합도를 두고 의견이 갈렸을 때 코드를 함께 검토해 팀원이 제안한 델리게이트 방식 채택
  • 프로토타입·알파·베타 단계를 주 단위 작업으로 나누고, 매주 진행 상황을 점검하며 우선순위 조정
